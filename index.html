Planificación de equipos

Cómo trabajar en el MVP de Vyntrix

Esta guía explica qué equipo hace cada funcionalidad, cómo empezar y qué deben entregar. Si eres desarrollador junior, aquí encuentras todo lo que necesitas saber.

Cómo usar esta guía: Primero revisa la distribución de equipos. Después busca tu grupo y los módulos que debes implementar. Al final revisa los sprints para las fechas y la sección de recursos con documentación y videos para aprender las tecnologías.

Cuenta y perfil deportivo

Registro de usuarios, selección de deportes, objetivos personales y perfil completo con nombre, edad, deporte principal, nivel y estadísticas.

Panel de rendimiento

Dashboard con resumen de entrenamientos realizados, tiempo total, progreso de puntos, posición en rankings y gráfica de evolución.
Listo cuando: Dashboard carga datos reales Gráfica muestra evolución Puntos y ranking visibles

Vicente y Gabriel — Entrenamientos y Retos

RF-02 · RF-05
Vicente · Gabriel
Backend
Módulos: RF-02, RF-05
API de Entrenamientos y Sistema de Retos
Solo backend (NestJS). Crean los endpoints que Frontend y Full-Stack van a consumir.
RF-02

Registro de entrenamientos (API)

Endpoint para crear, listar, editar y eliminar entrenamientos. Cada entrenamiento tiene: deporte, duración, distancia, calorías, fecha y notas.
Listo cuando: CRUD completo funcionando Validaciones activas Historial por usuario Documentación OpenAPI lista
RF-05

Sistema de retos (API)

Endpoint para crear retos, asignarlos a usuarios y calcular progreso. Retos semanales y mensuales con recompensas en puntos.
Listo cuando: CRUD de retos funcionando Progreso se calcula solo Puntos asignados al completar Documentación OpenAPI lista
Backend
Cómo empezar:
1 Esperar a que Fernando (DB) entregue las migraciones de tablas
2 Crear el CRUD de entrenamientos (RF-02) en NestJS
3 Documentar los endpoints con OpenAPI
4 Crear el CRUD de retos (RF-05) en NestJS
5 Implementar lógica de progreso y recompensas

Fernando y Gabriel — Base de Datos

Todos los módulos
Fernando · Gabriel
Base de Datos
Apoyo a RF-01 al RF-06
Modelar, crear y entregar la base de datos
PostgreSQL. Crean las tablas, migraciones y consultas que todos los demás equipos necesitan.
Entregable 01

Diagrama y tablas de la base de datos

Diseñar todas las tablas del sistema: usuarios, deportes, entrenamientos, puntos, niveles, logros, rankings, retos y participantes. Definir columnas y relaciones.
Listo cuando: Diagrama E-R aprobado Todas las tablas definidas Relaciones claras (claves foráneas)
Entregable 02

Migraciones y datos de prueba

Scripts SQL que construyen las tablas en PostgreSQL con datos de ejemplo: los 4 deportes (fútbol, running, ciclismo, fitness), los 4 niveles y retos de prueba.
Listo cuando: Migraciones ejecutables Seeders cargan datos iniciales Backend puede conectarse
Entregable 03

Consultas para rankings y estadísticas

Consultas SQL optimizadas para: ranking global y por deporte, cálculo de puntos totales, estadísticas de entrenamiento y filtros por temporada.
Listo cuando: Consultas de ranking funcionan Cálculo de puntos correcto Estadísticas agregadas disponibles
Base de Datos
Cómo empezar:
1 Reunirse con el equipo para definir las tablas necesarias
2 Crear el diagrama entidad-relación
3 Escribir las migraciones SQL
4 Crear seeders con datos de prueba
5 Entregar migraciones a Backend y Full-Stack

Sprints — Qué hacer y cuándo

3 sprints · 6 semanas

Cada sprint dura 2 semanas. Al final de cada sprint debe haber funcionalidad funcionando. No esperen al final para integrar.

Sprint 1 · Semanas 1 y 2
24 jul — 6 ago
  • DB: Diseñar tablas, migraciones, seeders
  • Backend: API de entrenamientos (RF-02)
  • Frontend: Pantalla Home + navegación
  • Full-Stack: Registro de usuarios (RF-01)
Sprint 2 · Semanas 3 y 4
7 ago — 20 ago
  • DB: Consultas optimizadas, índices
  • Backend: API de retos (RF-05) y puntos
  • Frontend: Pantallas Perfil y Ranking
  • Full-Stack: Panel de estadísticas (RF-06)
Sprint 3 · Semanas 5 y 6
21 ago — 3 sep
  • Todos: Conectar frontend con APIs
  • QA: Probar cada módulo
  • Ajustes: Corregir errores
  • Deploy: Publicar MVP
MVP v1.0 — 3 sep 2026

Dependencias

Esto es importante para no bloquearse. Si tu tarea depende de otro equipo, pídeles lo que necesitas con tiempo. Gabriel coordina para que nada se detenga.

Orden de arranque recomendado:
1 DB entrega las tablas a Backend y Full-Stack
2 Backend construye APIs y las documenta (OpenAPI)
3 Frontend y Full-Stack consumen las APIs
4 Gabriel integra todo y prueba que funcione
